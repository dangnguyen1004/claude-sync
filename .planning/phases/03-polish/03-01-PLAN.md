<task type="auto">
  <name>Task 4: Implement streaming archive creation for large conversation directories (EXP-08)</name>
  <files>src/packer.mjs</files>
  <action>
    Update src/packer.mjs to add createArchiveStreaming() function that handles large conversation directories without loading all files into memory/staging directory.

    The current createArchive() copies all files to a staging directory first, then creates the archive. This works for small collections but exhausts memory/disk for multi-GB conversation histories (3.8 GB+).

    **New function: createArchiveStreaming(scannedFiles, outputPath, manifest, claudeDir)**:
      Uses tar's streaming API to add files one at a time directly to the archive without a staging directory.

      **Approach**:
        1. Create a PassThrough pipeline: archiveWriteStream → gzip → tarParser → tarWriteStream
        2. The tar writer uses `tar.entry()` to stream each file into the archive as it's read
        3. Manifest.json is added first as a normal tar entry
        4. Each scannedFile is read via `fs.createReadStream()` and piped through `tar.entry()` using the pipe option
        5. Uses `finish` event to know when archive is complete

      **Alternative simpler approach** (if the PassThrough pipeline is too complex):
        Use tar's `file` option with a writable stream and `tar.add()` which can accept file streams:
        ```javascript
        import { createReadStream } from 'node:fs';
        import { pipeline } from 'node:stream/promises';

        // Create archive using tar.create with a file list that grows
        // Use tar.add() to stream individual files: tar.add({ name: 'path', file: createReadStream(absPath) }, archive)
        ```

      **Key requirement**: For conversations type files, use streaming reads (fs.createReadStream). For other types (small files), staging dir approach is fine.

      **Decision**: Implement a HYBRID approach:
        - For ALL files: use streaming tar.entry() approach to avoid staging dir memory pressure
        - This simplifies the code (one code path) and works for all file sizes
        - The staging dir approach (createArchive) is no longer needed if streaming works correctly

      **Implementation steps**:
        1. Add to packer.mjs: `import { pipeline } from 'node:stream/promises';`
        2. Add `import { createReadStream } from 'node:fs';`
        3. Add `import { PassThrough } from 'node:stream';`
        4. Implement `createArchiveStreaming()`:
           ```javascript
           export async function createArchiveStreaming(scannedFiles, outputPath, manifest, _claudeDir) {
             const tmpOutput = outputPath + '.tmp';
             const writeStream = createWriteStream(tmpOutput);
             const gzipStream = createGzip();
             const tarStream = tar.Stream(); // Use tar stream API

             // Wire up the pipeline
             tarStream.pipe(gzipStream).pipe(writeStream);

             // Add manifest first
             const manifestEntry = tarStream.entry({
               name: 'manifest.json',
               size: Buffer.byteLength(JSON.stringify(manifest), 'utf-8'),
             });
             manifestEntry.write(JSON.stringify(manifest, null, 2));
             manifestEntry.end();

           // For each scanned file:
           for (const f of scannedFiles) {
             const stat = await fs.stat(f.absPath);
             const entry = tarStream.entry({ name: f.relativePath, size: stat.size });
             const readStream = createReadStream(f.absPath);
             await pipeline(readStream, entry);
             entry.end();
           }

           tarStream.end();
           await finished(writeStream);

           // Atomic rename
           await fs.rename(tmpOutput, outputPath);
         }
        ```

      5. Update the imports in packer.mjs to include needed stream utilities
      6. Update export.mjs to use createArchiveStreaming instead of createArchive when conversations are included (detect by checking if 'conversations' is in activeTypes)
      7. For now, always use createArchiveStreaming (it handles all file sizes correctly, including small ones)

      **Error handling**: Wrap in try/catch. In finally block, clean up tmp file if it exists and any streams are left open.

      **Important**: The tar npm package's Stream API may differ. Check the actual tar npm v7.5.13 API for streaming creation. If the API doesn't support streaming creation cleanly, fall back to:
        - Using `tar.create()` with `cwd: claudeDir` and passing all file paths as the file list
        - This still avoids the staging dir for copying but uses tar's native file listing
        - The key benefit is avoiding the staging dir copy step, not necessarily true streaming
  </action>
