  <name>Task 4: Implement streaming archive creation for large conversation directories (EXP-08)</name>
  <files>src/packer.mjs</files>
  <action>
    Update src/packer.mjs to add createArchiveStreaming() function that handles large conversation directories without loading all files into memory/staging directory.

    The current createArchive() copies all files to a staging directory first, then creates the archive. This works for small collections but exhausts memory/disk for multi-GB conversation histories (3.8 GB+).

    **New function: createArchiveStreaming(scannedFiles, outputPath, manifest, claudeDir)**:
      Uses tar's `tar.create()` API with `cwd` option to avoid the staging directory copy. This is the standard approach for avoiding intermediate copies — tar reads files directly from their source locations.

      **Key insight for EXP-08**: The original `createArchive()` copies all files to a staging directory first, then archives from there. For multi-GB conversation histories, this doubles disk I/O and can exhaust disk space. By using `tar.create({ cwd: claudeDir }, filePaths)`, tar reads files directly from their source paths (relative to claudeDir) without a staging copy.

      **Implementation steps**:
        1. Write manifest.json to a temp location (still needed as a staging step since we can't stream it easily with tar.create)
        2. Build a file list of relative paths from scannedFiles
        3. Call `tar.create({ gzip: true, file: outputPath, cwd: claudeDir }, relativePaths)`
           - tar reads each file directly from claudeDir using the relative path
           - No staging directory copy needed — tar handles the file reads internally
        4. Wait for tar.create to complete (it's async)
        5. Clean up the temp manifest file

        ```javascript
        import tar from 'tar';
        import fs from 'node:fs/promises';

        export async function createArchiveStreaming(scannedFiles, outputPath, manifest, claudeDir) {
          // Write manifest to a temp file — tar.create needs files on disk first
          const manifestPath = path.join(claudeDir, 'manifest.json');
          await fs.writeFile(manifestPath, JSON.stringify(manifest, null, 2), 'utf-8');

          try {
            const relativePaths = scannedFiles.map(f => f.relativePath);

            // tar.create reads files directly from claudeDir using relative paths
            // No staging directory copy — tar handles file I/O internally
            await tar.create({
              gzip: true,
              file: outputPath,
              cwd: claudeDir,
            }, ['manifest.json', ...relativePaths]);
          } finally {
            // Clean up temp manifest
            await fs.unlink(manifestPath).catch(() => {});
          }
        }
        ```

      5. Update export.mjs to use createArchiveStreaming instead of createArchive when conversations are included (detect by checking if 'conversations' is in activeTypes). For now, always use createArchiveStreaming since it handles all file sizes correctly including small ones — the cwd approach is more efficient than staging-dir copy for any size.

      **Error handling**: Wrap in try/catch. If tar.create fails, the error propagates and export.mjs spinner fails accordingly.
